# 架构阅读室

[English](README.md) | [简体中文](README.zh-CN.md)

NeuronMesh 是长期系统研究项目。本目录保存一个功能成为平台组成部分前必须满足的契约。

## 当前基线

- [系统架构](../../ARCHITECTURE.zh-CN.md)：目标平面、组件、状态所有权、门槛与实现差距。
- [状态与故障模型](STATE_AND_FAILURE.zh-CN.md)：请求、租约、记忆和角色状态机及故障测试。
- [任务协调调度](../TASK_ORCHESTRATION.zh-CN.md)：已实现的规划器、异步 Worker 槽位和服务截止时间逻辑。
- [接口契约](INTERFACE_CONTRACTS.zh-CN.md)：节点和服务共享的版本化对象。
- [威胁模型](THREAT_MODEL.zh-CN.md)：信任边界、威胁登记、控制和残余风险。
- [决策日志](DECISIONS.zh-CN.md)：已采用的架构决定及反转成本。
- [质量场景](QUALITY_SCENARIOS.zh-CN.md)：调度、故障、记忆、角色、安全和学习的可观测验收结果。

## 状态用语

| 状态 | 含义 |
| --- | --- |
| `Proposed` | 正在讨论，没有实现承诺 |
| `Accepted` | 新工作的必需方向，实现可能仍不完整 |
| `Implemented` | 契约、一致性测试和故障测试均存在 |
| `Superseded` | 已被链接的新决定替换 |

只有满足 `Implemented` 条件后，才能把对应能力描述为已实现。当前仓库默认应称为参考切片。

## 变更检查清单

任何影响架构的变更都必须描述：

1. 权威状态所有者；
2. 生命周期和幂等性；
3. 兼容与迁移；
4. 故障、分区和重试行为；
5. 安全与隐私边界；
6. 回执和遥测；
7. 一致性证据；
8. 回滚/降级路径；
9. 不支持场景。

架构预期会持续多个版本仍不完整。小而经过验证的子系统优于宽泛但未经验证的主张。
