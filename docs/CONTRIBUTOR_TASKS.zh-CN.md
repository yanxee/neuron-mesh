# 贡献任务板

[English](CONTRIBUTOR_TASKS.md) | [简体中文](CONTRIBUTOR_TASKS.zh-CN.md)

以下任务是新贡献者的限定起点。请先阅读[加入 NeuronMesh](JOIN.zh-CN.md)，再在开始修改 API、基准主张或存储格式前评论或创建对应 Issue。

## 如何认领工作

1. 选择一个你能完成并验证的成果，而不是整个子系统。
2. 评论说明计划产生的产物，以及用于证明的准确命令或指标。
3. 首次 Pull Request 应聚焦。文档、失败测试或可复现基准都是有效成果。
4. 如果任务已经超过一次可评审变更，请提出更小的第一切片。

只有在维护者或当前认领者确认无冲突后，任务才算被保留。如果 Issue 连续 14 天无活动且不存在草稿，其他贡献者可以申请继续。

## 架构关键任务

这些任务实现 [架构基线](../ARCHITECTURE.zh-CN.md)。它们有意大于首次贡献 Issue，可能需要拆分。

### A1. 创建版本化 Schema 包

- 将 `NodeCapability`、`CapacityLease`、`ModelManifest`、`StageManifest`、`RequestEnvelope`、`StepReceipt`、`MemoryObject`、`ReplicaManifest` 和 `RoleManifest` 转换为 JSON Schema。
- 增加有效/无效一致性夹具和未知关键字段行为。
- 记录 Schema 迁移和签名规范化。

### A2. 构建状态机测试框架

- 显式建模请求、租约、角色和记忆生命周期。
- 注入重试、过期、陈旧 fence、分区和重复投递。
- 复用[质量场景](architecture/QUALITY_SCENARIOS.zh-CN.md)。

### A3. 替换共享令牌授权

- 增加节点认证和命名空间级租户授权。
- 定义策略 epoch、撤销和短期租约。
- 将本地开发模式与外部试点明确分离。

### A4. 增加出站节点目标策略

- 拒绝回环、链路本地、云元数据和其他禁止目标。
- 阻止凭证跨重定向转发。
- 为被阻止连接增加可审计 SecurityEvent。

### A5. 实现签名步骤与存储回执

- 定义幂等回执 ID 和规范化签名。
- 覆盖执行、存储确认、删除和配额使用。
- 证明重复重试不会产生重复核算记录。

## 适合首次贡献的任务

### 1. 增加远端流式推理代理测试 —— [Issue #1](https://github.com/yanxee/neuron-mesh/issues/1)

- 增加 gateway-to-gateway SSE 转发测试。
- 验证断开传播、超时和 `X-Neuron-Forwarded` 环路防护。
- 预期涉及文件：`neuron_mesh/peers.py`、`tests/test_api.py`。

### 2. 增加存储配额边界测试 —— [Issue #2](https://github.com/yanxee/neuron-mesh/issues/2)

- 测试用更大或更小 payload 替换已有备份。
- 测试超过承诺容量时的 HTTP 507。
- 验证不会报告部分副本确认。

### 3. 增加网络能力探测

- 测量两个节点之间的双向延迟、抖动和近似吞吐。
- 持久化 EWMA 结果，但不覆盖节点签名的静态能力。
- 提供可配置超时和确定性测试替身。

### 4. 增加角色迁移故障恢复

- 增加端点或命令，将源角色从 `migrating` 恢复为 `active`。
- 测试错误目标 ID、错误传输密钥和过期传输策略。

### 5. 增加命名空间授权

- 引入所有者范围令牌，替换整个邀请网共享 Bearer Token。
- 增加测试证明一个命名空间不能读取另一个命名空间。
- 记录从开发令牌迁移的方案。

### 6. 增加 Docker 冒烟测试 —— [Issue #3](https://github.com/yanxee/neuron-mesh/issues/3)

- 增加 CI 任务，验证 Compose 配置并启动两个容器。
- 验证就绪、节点发现、记忆复制和冷召回。

### 7. 增加终端演示录制脚本

- 使用 Echo 后端创建确定性演示。
- 展示状态、远端路由、加密备份和冷召回。
- 将转录发布到 `docs/`。

### 8. 增加模型后端适配器契约

- 为 llama.cpp、vLLM 和测试后端定义稳定接口。
- 包含模型列表、健康、聊天和取消。
- 增加模拟适配器和一致性测试。

## 研究贡献

### 9. 基准测试资源感知调度

在固定硬件和工作负载下，对比随机、仅 RTT 和完整能力感知路由。

### 10. 基准测试热/温/冷记忆策略

比较仅本地、热层加远端备份、自适应驱逐。报告 Recall@K、token 成本、存储和恢复延迟。

### 11. 评估记忆投毒防御

构建跨会话注入金丝雀集，测量隔离率、误报率和可用性成本。

### 12. 测量主机类型行为

至少在服务器、台式机、笔记本和 ARM 小主机上测试热、电池和网络变化。发布持续吞吐，而不是峰值跑分。

### 13. 运行兼容性实验室

- 在 Windows、Linux、macOS 或小型 ARM 设备上运行确定性双节点演示。
- 报告操作系统、架构、Python 版本、Docker 可用性、准确命令和非敏感输出。
- 即使失败，也创建兼容性/部署报告。
- 将重复失败转化为带最小复现的聚焦 Bug。

### 14. 编写公网传输决策记录

- 比较 libp2p QUIC 与最小认证 HTTPS/WebTransport 设计。
- 覆盖 NAT 穿透、中继回退、身份绑定、重放、发现和分区恢复。
- 包含家庭 NAT、CGNAT、移动网络和 UDP 被阻止的测试矩阵。
- 这是架构提案，不要求首个 PR 实现完整传输。

### 15. 定义空间适配器一致性套件

- 定义版本协商、权限检查、断开行为和有界事件顺序。
- 提供浏览器模拟和一个与引擎无关的夹具。
- 包含旁观者隐私和不可信模型输出场景。
- WebXR/OpenXR 可选依赖必须放在适配器之后。

## 任务质量标准

新贡献者可以开始的任务必须说明：

- 当前行为及为何不足；
- 最小可接受成果；
- 可复现验证命令或指标；
- 相关文件或文档；
- 明确非目标和失败边界。

## 如何提出工作

使用功能请求 Issue 模板，包含：

1. 问题和受影响用户；
2. 最小可测试变更；
3. 基准或正确性标准；
4. 失败模式和非目标；
5. 是否改变协议、记忆或信任语义。
